# Decisions

| Date | Decision | Why | Alternative rejected |
|---|---|---|---|
| 2026-10-13 | `three@0.186.1`, pinned. The only runtime dependency (~150 KB of the 185 KB gzip bundle). | Rendering engine required by the brief. | WebGPU renderer: weaker reach on low-end Android and older iPads. |
| 2026-10-13 | Dev-only dependencies, 0 KB shipped: `vite@8.3.4`, `vitest@5.0.4`, `typescript@7.0.2`, `@types/three@0.186.0`, `@types/node@24.19.2`. | Build, test, types. | — |
| 2026-10-13 | Content validation is a hand-written check in `tests/unit/content.test.ts`. | Zero dependencies, runs in CI, and also covers file existence (models, strokes, VO lines). | `zod`: an extra dependency for the same checks. |
| 2026-10-13 | Remaining 3D assets are built in code (`src/procedural/`), not with Higgsfield: rock, bush, island, path, pond, sky, clouds, grass, flowers. | Owner's decision; credits ran out after 18 GLBs. Low-poly merged meshes, one draw call each. | Generating the rock and bush with Higgsfield (30 credits each). |
| 2026-10-13 | Glyphs are drawn on canvas; the "3D" letter is a stack of glyph-shaped layers (2 draw calls). Since 2026-10-14 they're drawn in the self-hosted Baloo fonts (row below). | Works for Latin and Tamil with no outline extraction. | `opentype.js` + `build-letters.ts` extruded outlines: a build step and more geometry for the same look. |
| 2026-10-13 | Mini-games run on a separate play meadow (world z = 95), not at the bud. | Clean, predictable layout for every template; the garden never occludes the game. | Playing in place at each bud. |
| 2026-10-13 | All SFX and the music loop are synthesised with Web Audio. Music ducks to 0.12 while VO plays. | No audio assets exist yet; zero bytes to download. | Shipping placeholder audio files. |
| 2026-10-13 | VO uses `speechSynthesis` (en-IN, ta-IN when available, otherwise a chime). Recorded files plug in through `vo-manifest.json` with no code change. | Brief §6.4 placeholder plan. | — |
| 2026-10-13 | Basket Match says the letter name ("Which one starts with C?") rather than a phoneme. | TTS reads phoneme spellings badly; recorded VO can switch `{sound}` to the real sound. | Phonetic spellings such as "kuh". |
| 2026-10-13 | Sing-along stand-in: a camera rail past every bud with spoken lines. | No song or cue file exists yet. **TODO(content):** song + `cues.{lang}.json` + Cue Recorder. | Leaving the gazebo inert. |
| 2026-10-13 | GLB textures shrunk to 512² JPEG (q85) before import. Superseded 2026-10-14 by `optimize-assets`. | Brought every model except the gazebo under 400 KB. | Shipping the raw 1.2–3.6 MB GLBs. |
| 2026-10-13 | No `ASSETS.md` licence log, by the owner's choice. | Owner instruction. Brief §10.6 asks for one before shipping to schools. | — |
| 2026-10-13 | `vite-plugin-pwa@2.0.0` (dev; pulls `workbox-build`/`workbox-window` 7.4.1). Ships `sw.js` 0.9 KB + Workbox runtime 7.1 KB gzip. | The brief's choice; supports Vite 8; generates the precache manifest from the build. | A hand-written service worker: less tooling, but the precache list and revisioning would need maintaining by hand. |
| 2026-10-13 | Precache the app shell only (13 files); models and audio use runtime CacheFirst (`buzzy-packs`). On a first visit the game waits ≤ 4 s for the worker to control the page before loading models. | Each model is downloaded once, and all 18 are cached after one visit (the other language warms in the background). | Precaching every GLB: downloads ~3.9 MB twice on the first visit. |
| 2026-10-13 | Service worker registered by hand (`src/core/offline.ts`); `injectRegister: false`. | The plugin's inline register script would violate the `script-src 'self'` CSP. | `injectRegister: 'inline'`. |
| 2026-10-13 | PWA icons drawn by `scripts/make-icons.mjs` (Node zlib, no dependencies). | Reproducible, no design tool or extra package. | `@vite-pwa/assets-generator` (adds sharp). |
| 2026-10-13 | `@playwright/test@1.64.0` (dev) on the installed Google Chrome (`channel: 'chrome'`). | No ~150 MB browser download; GitHub's runners have Chrome preinstalled. | Bundled Chromium (`npx playwright install chromium`), one config line away. |
| 2026-10-13 | E2E runs a production-optimised `--mode e2e` build that exposes `window.__buzzy`; the test hook is compiled out of the real production bundle. | Lets tests drive moving 3D targets reliably without shipping test code. | Testing the dev server (no service worker, unminified code). |
| 2026-10-13 | Tamil glyph screenshot tests capture a static 2D Glyph Sheet (`/?dev=glyphs`) drawn with the game's own glyph functions, not the 3D scene. Plus an ink-signature check (has ink, isn't the missing-glyph box, all six distinct). | Deterministic pixels; the WebGL scene animates and its anti-aliasing varies by GPU. The signature check catches a broken font even if someone accepts a bad baseline. | Screenshotting the running game. |
| 2026-10-13 | Screenshot baselines are per platform (`*-darwin.png` committed); 1% pixel tolerance, and tighter per-pixel colour matching on the tracing boards because the letter is faint there. | Fonts differ by OS. A mutation check (ஆ swapped for அ) fails three tests. | One cross-platform baseline: needs a self-hosted font first (Baloo Thambi 2), which would also make CI baselines match macOS. |
| 2026-10-14 | `scripts/optimize-assets.ts`: in place, idempotent (stamped `buzzyPipeline: 1`), simplify only over budget, WebP ≤ 512², meshopt compression. Models went from 3.9 MB to 1.4 MB, and the gazebo from 519 KB to 208 KB. | Brief Phase 6; any AI-made GLB can be dropped in. Before/after renders differ by ≤ 0.2% of pixels per model. The one visible change is a small wedge at the fly's wing root, from trimming it to its 2,000-triangle budget. | KTX2 textures: needs a ~200 KB WASM transcoder at runtime. Draco: a larger decoder than meshopt. |
| 2026-10-14 | Dev dependencies for the pipeline (0 KB shipped): `@gltf-transform/core`, `functions`, `extensions` 4.5.1; `meshoptimizer` 1.3.0; `sharp` 0.35.5 (prebuilt binary, no install script). Runtime: three's bundled `MeshoptDecoder` (+~8 KB gzip). | Standard glTF tooling; the decoder is self-hosted inside the bundle. | — |
| 2026-10-14 | CSP `script-src 'self' 'wasm-unsafe-eval'`. | The meshopt decoder compiles WebAssembly. This allows WASM only, not JavaScript `eval`. | Uncompressed GLBs (would break the size budgets). |
| 2026-10-14 | `scripts/check-budgets.ts` runs at the end of `npm run build` and fails it on any exceeded budget (69 checks). Per-model triangle budgets live in `scripts/model-budgets.json`. | Brief §7.4: "the build fails if any is exceeded". | A CI-only check. |
| 2026-10-14 | Quality tiers differ from brief §7.3 in one way: no shadow maps on any tier (the brief has 1024/2048 maps for mid/high). Tiers vary pixel ratio, particle budget and decorative-flower density instead. | Blob decals already ground every object, and a shadow pass would roughly double garden draw calls past the 80 budget. | Shadow maps on mid/high. |
| 2026-10-14 | Frame-time governor: a boot probe (2 s after 0.5 s of warm-up; > 33 ms → −1 tier, > 45 ms → −2), then −1 tier when the 3 s rolling average exceeds 40 ms. Never steps up. Uses the loop's clamped dt (max 50 ms), which still detects every frame over 40 ms. | Brief §7.3 rules. Never stepping up avoids visible quality flicker. The probe runs while the Play button waits, so the child doesn't notice. | Stepping back up on recovery: can oscillate on thermally throttled phones. |
| 2026-10-14 | The tier is not saved between visits. | Storage holds only the brief's five fields (§7.3), and the boot probe re-detects a slow device within ~2.5 s. | Persisting the tier. |
| 2026-10-14 | iOS/iPadOS silent switch no longer mutes the game: `navigator.audioSession.type = 'playback'` (Safari 16.4+), set on the first tap. Fallback for older iOS: an in-memory silent WAV looped through `<audio>`, paused whenever the game is in the background (`src/core/audioSession.ts`). | Children's devices often sit on silent. Video and game apps play through the switch; the HUD mute button and the grown-ups volume still silence the game. | Respecting the switch (silent game on many devices). Always using the silent loop (it can leave Now Playing controls on the lock screen). |
| 2026-10-14 | Self-hosted fonts: Baloo 2 Latin + Baloo Thambi 2 Tamil, weight 800, from `@fontsource/baloo-2` and `@fontsource/baloo-thambi-2` 5.3.0 (dev deps, OFL 1.1), copied to `public/fonts/` by `npm run fonts` with `OFL.txt`. 36 KB in total, precached for offline. | Brief §7.3 fonts. Script-level subsets (all of Latin, all of Tamil) instead of per-letter ones, so adding a letter never needs a new font build. | Subsetting to the exact glyphs in use: saves ~25 KB but breaks the "new letter = JSON only" rule. |
| 2026-10-14 | Fonts load through the FontFace API as one family ("Buzzy Glyph") split by unicode-range, and the game waits for them before drawing any letter texture (max 4 s, then platform fonts). | Canvas text never waits for web fonts, so without this the first textures would be drawn in a fallback font and cached that way. | CSS `@font-face` alone. |
| 2026-10-14 | The tracing board places the letter exactly as the Stroke Editor shows it (centred, ink filling 90% of the box: `TRACE_GLYPH_FIT`). The B and E paths were re-derived from Baloo's measured geometry (stem, bar and bowl centrelines). | Before, the board fitted the letter to the path's bounds and the editor centred it, so authored paths couldn't line up; and Baloo is heavier than the font the old paths followed. | Fitting the letter to the path (letters drift as paths change). |
| 2026-10-14 | Cue Recorder (`/?dev=cues`, dev + QA builds): records cues from key presses (1–6, or A–F in English) or tile taps against `audio.currentTime`; waveform with markers; undo, shift-all and per-cue edits; paste-in import; Preview with a lateness report; exports `cues.{lang}.json`. `src/core/cues.ts` holds validation and `CueTracker`, which the song-driven sing-along will reuse. | Brief §5.6 / Phase 3. A test with a generated dummy song shows every cue firing within 50 ms (Phase 3 acceptance). | Recording against a Web Audio clock (more code; the media element's clock is what playback uses anyway). |
| 2026-10-14 | Songs are listed in `src/data/songs.json` (null until a file exists) instead of probing for `song.{lang}.mp3`. | A probe for a missing file logs a 404 console error and fails the e2e error check; an explicit list is also what the sing-along will read. | Probing a conventional path. |
| 2026-10-14 | Song sing-along (`src/scenes/SongSingAlong.ts`): driven by the song element's clock and `CueTracker` in the game loop; approaches start so Buzzy and the camera arrive on each cue, and cues under 1.1 s apart keep the wide shot. Each letter's glyph and object pop is built before the song starts. The spoken version stays as the fallback. | Brief §5.6. Every cue fires within 50 ms in the e2e test. Building the pops first means a cue never waits on a load. | Per-cue tweens timed off the game clock (drifts from the audio). |
| 2026-10-14 | The song is fetched whole and played from memory (blob URL) through one `<audio>` element that's created and silently unlocked in the first Play tap, then routed through the song bus. | iOS only lets media play from a tap (the song starts seconds after the gazebo tap); range requests through the offline cache break in Safari; the bus keeps mute and volume working, iOS included. | Decoding to an AudioBuffer: about 60 MB of PCM for a 3-minute stereo song on a 2 GB phone. Streaming the element directly: fails offline on Safari. |
| 2026-10-14 | Generated music is held while the song plays; nothing speaks during it (the intro is said first). | Brief §8: never play VO and the sung line at the same time. | Ducking the music under the song. |
| 2026-10-13 | Tamil stroke files for ஆ and உ are placeholders. | Brief: the owner authors Tamil stroke order with `/?dev=strokes`. | — |
